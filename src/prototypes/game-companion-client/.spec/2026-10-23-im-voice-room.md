- 目标平台：Windows 客户端，1920×1080 CSS 像素画布

- 路由分类：`frontend`

## 需求决策

| 问题 | 用户选择 | 最终决策 |
| --- | --- | --- |
| 本轮功能范围 | IM 私聊与语音房都做，先独立呈现 | 增加“消息”和“语音房”两个独立导航入口，不建立 IM 与房间的消息联动 |
| IM 会话 | 私聊、群聊和好友 | 支持基础好友列表、私聊、群聊；不做加好友、删除好友和备注 |
| 好友能力 | 基础好友列表 | 展示好友和状态，可从好友资料发起私聊 |
| 群聊能力 | 创建群聊、邀请好友 | 创建时填写群名称并选择至少两位好友；群聊内可继续邀请好友 |
| IM 内容 | 文字、表情、图片、语音 | 均以本地可点击的演示交互展示，不接真实发送、上传或语音服务 |
| 会话列表 | 接受建议范围 | 支持会话搜索、私聊/群聊筛选和未读提示 |
| 语音房结构 | 参考 KOOK Web 截图 | 房间/子频道树、麦位区、房内文字聊天三栏 |
| 视觉方向 | 保留浅色灰阶主题 | 使用灰阶主题 token 和组件，仅借用参考截图的信息结构 |
| 语音房操作 | 加入互动和房间管理 | 支持加入、上麦/下麦、静音、离开，以及创建和设置房间、成员管理 |
| 房间可见性 | 公开、私密和邀请加入 | 房间设置只包含名称和公开/私密；私密邀请在语音房入口处理，不进入 IM |
| 房间成员管理 | 移出、禁言、设置房主/管理员 | 房主和管理员可移出/禁言；房主可设置管理员或转让房主 |
| 子频道 | 房主可新增、改名、删除 | 每个新房间默认含“主频道”；删除有成员的频道时迁移到其他有空位的频道 |
| 子频道成员交互 | 支持拖动用户进入子频道 | 房主/管理员可拖动成员；普通成员可点击频道自行切换 |
| 麦位 | 接受 8 个固定麦位建议 | 每个子频道 8 个固定麦位 |
| 房间邀请 | 邀请入口弹窗选择好友 | 接收方在语音房入口看到邀请和未读提示，可接受或忽略 |
| 资料面板 | 点击用户头像展开 | IM 聊天对象、消息发送者和群成员头像打开资料面板 |
| 页面状态 | 沿用项目状态规范 | 消息和语音房均支持正常、加载、空、异常状态；复杂房间页面展示房主、管理员、普通成员差异 |

## 设计决策

- 消息页为会话/好友列表 + 聊天内容两栏；用户资料面板默认收起，点击头像后展开。
- 语音房按参考图使用房间与子频道树、当前子频道 8 个麦位、房间文字聊天三个内容栏；客户端自身导航仍作为最左侧应用导航。
- 使用主题规定的浅灰画布、白色表面、细灰边框、系统字体和焦点状态，不采用 KOOK 截图中的深色配色。
- 房间聊天按房间分别保存本地演示记录，并与 IM 会话列表隔离。
- 本轮所有账号、好友、消息、邀请、角色、房间和子频道数据均为本地 mock；正式数据结构、持久化、实时语音和权限策略待后续产品/研发文档确认。
