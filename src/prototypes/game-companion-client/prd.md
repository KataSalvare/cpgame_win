# 游戏陪玩平台 Windows 客户端 PRD

## 1. 产品定位

- **对象类型**：前端原型
- **用户**：寻找俱乐部与陪玩的玩家
- **平台**：Windows 桌面客户端，1920×1080 CSS 像素画布
- **目标**：让玩家浏览游戏、俱乐部和陪玩服务，完成下单演示、账户管理，并通过 IM 和语音房与好友沟通及组队。
- **当前原型范围**：独立登录页、首页、大神列表、全局搜索、实名认证演示、俱乐部详情、陪玩资料、下单结算、个人中心、钱包、充值、优惠券、尊享卡、订单、消息、语音房、一键匹配浮层、屏幕录制演示和平台客服演示弹窗。客服演示仅在本地展示，不接入真实客服、工单或服务端通信；屏幕录制仅模拟交互状态，不采集或保存屏幕内容；关注、拉黑和打赏也不接入真实业务。

## 3. 内容与交互约束

- 首页俱乐部范围初始为「推荐俱乐部」，标签初始为「全部标签」，游戏范围初始为「全部游戏」。范围组在推荐和我关注的俱乐部中单选，标签组在全部标签和各个标签中单选；范围、标签和游戏三组筛选可组合生效。
- 年龄选项：18–25 岁、26–30 岁、31–35 岁、36–40 岁、40 岁以上。
- 陪玩筛选每个字段单选，各字段组合生效。服务列表游戏筛选单选，默认全部游戏。
- 服务排序：综合排序、价格从低到高、价格从高到低、单数从低到高、单数从高到低。
- 首页点击俱乐部进入俱乐部详情；点击陪玩后使用公共 WindowsClient 右侧面板展开第三栏，切换陪玩时保持俱乐部详情不变。内部路由为 `#page=home|club-detail&club=<id>&companion=<id>`，关闭第三栏后保留当前俱乐部详情。
- 每个页面的异常状态提供本地重试反馈；空状态提供返回或清除筛选的路径。
- 公告列表按发布时间倒序；未读状态仅在当前原型会话保留，刷新后恢复 mock 初始状态，不代表正式已读持久化规则。
- 下单结算为单页流程，单笔订单仅包含一项服务；“选择服务”使用带搜索的游戏、玩法、等级、服务四项级联选择，前一项选定后才可选择下一项，搜索可按完整路径定位服务。所有入口均可重新选择完整路径。暂不可接单的服务不可选。时长可填写正整数并通过加减按钮调整；小时服务可快捷选择 3、6、12 小时，局服务按局数填写；时长与单价相乘得出演示金额。订单备注选填，最多 50 字，不选择预约时间。
- 演示支付成功后，本地余额扣减并在订单列表新增“待接单”记录；不调用真实支付或持久化接口。余额不足时仅提供跳转钱包入口。
- “我的钱包”同页展示两个钱包；点击对应明细入口后，在第三栏展示该钱包的收支记录，关闭第三栏回到钱包。钱包提供优惠券和我的尊享卡入口；优惠券按可用、已过期、已使用分类。充值页可选当前档位可用的优惠券及微信支付、支付宝、苹果支付。俱乐部详情可查看该俱乐部的多种尊享卡和权益浮层；钱包只列玩家已拥有的卡。
- 充值和尊享卡购买仅在本地更新演示余额、优惠券状态和尊享卡持有状态；档位金额、优惠券适用/抵扣规则、尊享卡价格和权益内容均为 mock 示例，不代表正式业务规则。支付方式仅作选择展示，不连接第三方支付。
- 我的订单使用紧凑行列表和顶部状态标签筛选；行内分列展示订单号、陪玩及所属俱乐部、游戏/玩法/等级/服务信息、时长、服务单价与订单金额，并提供按状态变化的快捷操作（不含联系陪玩）。联系陪玩仅在订单详情的陪玩信息区提供。账号安全、通知、黑名单与退出登录交互位于个人资料常用设置中，均为本地原型状态，不代表服务端能力。
- 消息入口包含会话和好友；消息类型含文字、表情、示例图片和示例语音。群聊创建需填写群名称、选择至少两位好友；群内可以继续邀请好友。
- 语音房入口和消息入口独立。房间包含独立聊天，可发送文字、表情和图片；创建分组可设置名称及最大人数（1–100，默认25），默认公开。新分组默认创建公开“房间A”，每个房间可设置 1–8 人上限并据此展示麦位。

- 语音房房主/管理员可禁言、移出或拉黑成员，每项操作均需二次确认；只有房主可分配管理员，不提供转让房主。邀请由独立弹窗选择好友，接收邀请显示在语音房入口；私密房仅通过邀请进入，邀请不会发到 IM。
