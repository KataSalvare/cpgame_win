# 内容层导航与工具层选中项不同步

## 现象

从客户端内容层打开工具入口或切换个人中心模块后，页面内容已变化，但左侧工具导航仍选中旧入口；工具入口切换后，内容上下文或返回位置也可能丢失。

## 根因

- 内容层用 URL hash 表示客户端内部页面和模块，工具层用 pathname 表示当前预览入口。两者必须由 `tools/App.tsx` 双向同步。
- hash 变化后，若 React Router 只导航到 pathname，会丢掉当前 hash。目标路由的默认 hash 随后覆盖上下文，导致内容回到默认页。
- 帮助、录屏、通知、关闭应用和客服等浮层由本地状态打开时，如果不同时写入路由标记，工具层无法选中对应入口。
- 跨工具路由仅用组件 `useRef` 保存返回地址不可靠；原型路由变化可能重建组件实例，ref 会重置。
- 个人中心 Tab 只更新组件本地状态时，工具层监听不到模块切换。

## 实现约定

- `tools/App.tsx` 根据 hash 解析内容层目标入口；调用 `navigate` 切换 pathname 时必须附带当前 `window.location.hash`。
- 叠加式工具入口使用 `tool` 或 `support` 标记；打开时保留底层 `page`、`section` 等上下文，关闭时移除标记，让 pathname 回到对应入口。
- 系统设置属于整页路由；进入时把原 hash 序列化到 `returnHash`，返回时恢复，不能只靠跨路由组件 ref。
- 个人中心模块入口必须同时维护三处映射：工具页面配置的 `entryView`/`defaultHash`、`App.tsx` 的 hash 解析与规范化、内容层模块状态初始化。
- 内容层个人中心 Tab 通过 `profileNavigation.ts` 更新 hash；财富等级、我的访问、我的社交、陪玩入驻、我的俱乐部和注销账号分别映射到对应工具入口。快捷面板中的财富和社交快捷入口也使用相同路由助手。
- 新增工具层入口时，同时验收“从工具导航进入”和“从内容层触发”两条路径，并确认关闭浮层或返回后恢复预期上下文。

## 本次覆盖入口

系统设置、帮助中心、屏幕录制、客户端通知、关闭应用、俱乐部客服、平台客服、个人中心的陪玩入驻/我的俱乐部/注销账号，以及财富等级、我的访问和我的社交。
