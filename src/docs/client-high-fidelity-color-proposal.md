# Windows 客户端高保真着色规范（候选稿）

## 目的与适用范围

以用户提供的消息页 UI 截图为视觉参考，结合现有 Windows 客户端原型，建立全页面着色的起点。本文是**待确认的设计候选**，不是已生效的主题，也不改变现有页面的功能、字段和交互。正式业务仍以对应 PRD、客户端 SPEC 和用户最新要求为准；消息、订单等内容均为原型 mock。

参考图是 1818×969 的截图，颜色为截图采样近似值，尺寸受截图缩放影响；不能视为设计源文件中的精确 token。参考图只覆盖消息页，其余页面的视觉用法是基于现有原型的设计建议，须逐页验证。

## 视觉判断

整体为明亮的游戏客户端：高饱和黄色承担品牌和主要操作，冷白灰大面积承载内容，纯白组件浮在背景上；深色文字、少量红色通知和绿色在线状态形成层级。顶部黄条、浅灰侧栏、淡冷灰消息区使窗口结构一眼可辨；消息通过左右方向、头像和气泡区分，卡片以圆角与底色区分类型。礼物、头像、表情等素材提供局部丰富度。

参考图中的红点、等级、订单状态与操作仅作视觉观察，不据此新增业务规则。尤其会话右键菜单、发送者身份、群聊权限及页面状态仍按现有 PRD/SPEC 实现。

## 颜色建议

以下为上色候选值；“采样”指截图像素，并非原始设计标注。优先沿用已有语义变量，实际实现前确认映射及对比度。

| 语义 | 候选值 | 应用 |
| --- | --- | --- |
| 品牌黄 | `#FFD709`（采样；可与既有 `#FFD60A` 统一） | 顶栏、主要按钮、己方文字气泡、选中标记 |
| 页面冷灰 | `#F6F7FD`（采样） | 消息内容区及适合的内容背景 |
| 导航灰 | `#ECECEC`（采样） | 客户端左侧导航底色 |
| 白色表面 | `#FFFFFF`（采样） | 普通卡片、输入区、浮层、对方消息 |
| 浅黄强调 | `#FFEB85`（采样参考） | 特殊分享卡、品牌相关局部强调；避免作为普通卡片默认底色 |
| 主要文字 | `#1D2129`（沿用现有 token） | 标题、正文、黄色按钮文字 |
| 次级文字 | `#4E5969`（沿用现有 token） | 次要正文、图标 |
| 辅助文字 | `#4E5969`（沿用现有 token） | 时间、辅助信息等需要阅读的小字；`#86909C` 不用于普通文字 |
| 装饰分隔线 | `#E5E6EB`（沿用现有 token） | 非必要的栏位分界；不可单独用于识别控件边界 |
| 危险/未读 | `#C9362B`（沿用现有 token） | 错误、删除、未读计数 |
| 成功/在线 | `#287A4B`（沿用现有 token） | 在线和成功状态，配文字或图标 |
| 链接 | `#2F66C5`（沿用现有 token） | 可点击链接；参考图中的紫色链接暂不扩展为通用色 |

黄色底面配深色文字；红、绿、橙等状态不能只靠颜色区分。普通文字对背景的对比度至少 4.5:1，大文字至少 3:1；必要的控件边界和状态标识与相邻颜色至少 3:1。`#86909C` 在白底约 3.24:1、冷灰底约 3.03:1，不用于时间等普通文字；品牌黄在白底约 1.4:1，不能单独作为焦点环、选中细线或必要控件边界。装饰分隔线无需承担控件边界识别。截图中的浅灰小字和黄底白字不得直接照搬。

## 结构与组件

- **窗口**：沿用 1920×1080 CSS 像素固定画布及现有布局；工作台仅等比缩放。参考图顶栏为黄色、左侧为灰色，但截图比例不作为改动标题栏高度或导航宽度的依据。
- **导航**：图标与文字以深色为主，当前项用白色圆角底、黄色短标记或图标强化；未读使用带数字的红色徽标。分组继续服务现有导航结构，不因参考图增删入口。
- **按钮**：主操作为黄色填充、深色文字；次操作使用白底和深色文字/边框。圆角可由当前 6px 向更柔和的 8px 调整，胶囊按钮用于突出主操作或筛选，不要求所有按钮胶囊化。
- **输入和筛选**：搜索框、聊天输入区采用白底，筛选项以白色或黄色区分选中状态；保留标签、可访问名称与清晰焦点环。禁用、悬停和按下状态须明确，不能仅降低透明度到不可读。
- **卡片与面板**：普通信息白底，建议 8–12px 圆角、1px 淡边框；阴影主要给弹层而非常规卡片。头像、游戏封面与礼物素材保留各自颜色，避免额外随机着色。
- **菜单和弹窗**：白底、轻阴影、清晰分组；危险操作使用语义红及明确文案。遵循现有二次确认和锚定浮层规范，保持键盘访问、焦点与关闭路径。
- **消息**：对方白色气泡、自己黄色气泡；左右位置及头像同时区分发送方。名片、房间、订单、礼物、评价等维持各自内容结构，特殊卡片可少量使用浅黄；时间居中弱化。原型中私聊、群聊和悬浮聊天的身份展示规则以 SPEC 为准。
- **字体与间距**：系统字体沿用 `"Segoe UI", Arial, sans-serif`，中文使用系统回退。以 14px 正文、12px 辅助、20px 页面标题为基础；以 4px 为间距单位，常用 8/12/16/24px。具体紧凑区域需按实际内容验证，不由截图像素反推。
- **动效**：沿用 120–160ms 的轻量状态过渡及减少动态效果设置，状态变化本身应可辨认。

## 组件状态与落地约束

以下为确定的表达要求；具体状态色和像素值在消息页样板中确认后再统一到主题：

| 状态 | 必须体现 |
| --- | --- |
| 默认 | 控件、文字和背景可区分，图标按钮有可访问名称 |
| 悬停 | 可交互元素有反馈，不引起布局位移；不替代选中状态 |
| 按下 | 与默认和悬停状态可区分，松开后恢复对应状态 |
| 选中 | 以背景、形状、字重或图标等组合表达；不能只依赖黄色细线或颜色差异。列表选中与悬停可同时辨认 |
| 键盘焦点 | 显示连续、清晰的深色焦点环，在白色、冷灰和黄色背景上分别验证；弹窗打开时管理焦点，关闭后还原至触发入口 |
| 禁用 | 通过控件状态和文字或图标表达不可操作，不仅靠颜色或透明度；必要说明保持可读 |
| 加载和错误 | 保留原型既有状态及提示；错误说明靠近相关内容，异步状态变化可被辅助技术感知 |

确定各语义的用途后再映射到样式变量：至少区分页面背景、导航背景、普通表面、列表选中、输入区、己方气泡和对方气泡。现有变量可能被不同组件共用，不得仅全局替换色值而假定所有使用处都适合；逐个检查受影响页面和状态。控件尺寸、行高、圆角及状态具体色值通过消息页样板验证，避免直接覆盖现有紧凑布局。

图标、头像、等级徽章和礼物素材应统一风格、尺寸及缺失占位；品牌素材的来源和授权须确认。截图中的人物素材不能直接作为正式资产。图标的具体样式和素材清单待样板确认。

## 全原型应用顺序

1. 先制作消息页视觉样板，验证顶栏、导航、列表、输入区、消息气泡和菜单；覆盖私聊、群聊、卡片、未读、空/加载/异常及右键菜单，并确定字体、尺寸和组件状态。
2. 用首页或俱乐部页作为第二个样板，验证跨页面适用性；再验证大神、俱乐部及陪玩详情：沿用共享窗口和卡片语义，保留现有筛选、第三栏切换和主要操作。
3. 扩展到订单、钱包、购买和个人中心：强调金额、状态及危险操作；订单状态和交易提示仍以既有业务规格为准。
4. 验证语音房、匹配、聊天浮窗和公共弹层，检查素材、层级、遮挡、滚动和焦点；最后覆盖登录及其他独立入口。

每批以灰阶和上色两种模式检查相同交互，确认切换不重置状态；检查 1920×1080 画布、缩放、键盘焦点、对比度和常见状态。高保真包括素材和组件细节，不等同于简单替换颜色；缺失的图标、头像、品牌资源需另行确认，不能将截图内人物素材直接当作正式资产。

## 与现行规范的冲突及待确认

现有 [灰阶原型规范](../themes/grayscale-prototype/DESIGN.md) 的上色模式规定画布、面板和卡片纯白，禁止浅黄面板，并倾向 6px 控件、8px 卡片圆角。参考图则使用冷灰内容背景、灰色导航、浅黄特殊卡片及更圆润的局部控件。本文建议在现有灰阶基底上扩展高保真上色方案，但**是否替换现有上色模式、保留为另一种模式，以及冷灰/浅黄适用范围均待确认**。在确认并更新主题、token 与 SPEC 前，现行规范仍生效。

还需确认品牌黄的最终色值、字体和图标素材、各页面是否共用黄色顶栏，以及参考图之外的页面和深色场景是否另有设计稿。截图未提供原始字号、间距、状态色、渐变参数和交互状态；上述未标采样的尺寸与色值均为沿用或建议，而非从图中精确测得。
